# 写入侧复核：判断标准（写死版，2026-10-07）

复核表的 `label` 列只回答一个问题，其余一律不管：

> **这条内容，值不值得长期记住？**

不是"模型的类别标得对不对"，不是"标得完不完整"，也不是"措辞好不好"。

## 判断时依次问四句

1. **换个会话、换一天，还有用吗？**
   只在当下这一次对话里成立的（"帮我改一下""把这份总结成文档"）→ **0**。

2. **它里面有没有"新会话无法从代码/文件里恢复的东西"？**
   约定、禁忌、为什么这么选、当初排除了什么 → 有就倾向 **1**。
   能直接从代码读出来的事实（某个函数在哪、某个常量是多少）→ 倾向 **0**。

3. **它是"说了一件事"还是"要了一件事"？**
   陈述（决定/约定/教训/事实）→ 可留；请求（"请你…""能不能…""帮我…"）→ **0**。

4. **它会不会过期？过期后有没有人知道？**
   带"暂时/先别/之后"的，只有**耐久的那半句在**才算 1（例：把 key 放配置文件里配 = 约定，留；
   只写"暂时不处理 API key" = 定时炸弹，毙）。
   会过期且没有到期机制的，倾向 **0**。

## 明确要毙的几类（都在提示词里写着）

- 一次性任务指令、提问、寒暄、状态汇报、临时状态；
- 与项目无关的闲聊、没有项目特异性的通用常识（"要用 git 做版本管理"这种）；
- **模型的回答**、别人写的内容、粘贴进来的转录（哪怕内容对）；
- 只是复述/背诵教材知识（某个协议怎么工作、某个语言分几块内存），没有"他的取舍或他的项目"。

## 明确要留的几类

- 硬约定与禁忌（"接口一律 v2"、"不要动 data/ 目录"）；
- **带原因的**选型与取舍（"不用 Java，因为 DSH 插件方案不考虑"）；
- 踩过的坑：曾导致失败/返工的具体教训；
- 项目特有的事实：端口、路径、外部依赖的怪癖；
- 关于这个人自己的稳定事实：在做的事、能力短板、沟通偏好。

## 拿不准就用 `?`

`?` 不参与任何比率计算。**宁可填 `?`，不要为了"填满"而猜一个。**

## 边界例子（用来校准）

| 内容 | 判断 | 理由 |
|---|---|---|
| 用户要求把两种场景下的方法论分别总结，并沉淀成一份文档 | **0** | 只要了一份文档，没有方法论本身；以后问方法论，它答不上来 |
| 用户决定暂时不处理某个凭据，之后统一放到配置文件里配置 | **1** | 耐久的是"凭据归配置文件管"这条约定；"暂时"那半会过期 |
| 用户简历上有两条项目经历：设计并开发某并发处理机制…… | **1** | 关于他自己的项目事实，新会话从代码里恢复不到（**注意：这条是粘贴进来的，但判 1**） |
| 用户询问某个工具是否会把事件记录写入一个 db 文件 | **0** | 提问 |
| 用户对某缓存一致性协议的理解：三级缓存中前两级为某核心独有…… | **0** | 复述教材；不是他的项目取舍 |
| 用户明确表示某语言不选，所以方案定为该语言的原生插件 | **1** | 带约束力的选型决定 |

（例子是等价的合成内容，不是会话原文——真实语料按仓库惯例不进版本库。）
