## 自动注入：不看问题的那条路

自动注入（每个会话开头塞进提示的那段）**完全不看问题**：它按"重要度 ×0.85 + 时间衰减 ×0.15"排序，再按类型配额（硬约束 4 / 坑 3 / 已定决策 2）和 token 预算挑选。所以对它来说没有 Hit@K 可言，能测的是**覆盖率**：

| 指标 | 值 |
|---|---|
| 需要的记忆真的被注入了 | **2 / 36（6%）** |
| 每次注入的 token | 641（预算 600） |
| 注入条数上限 | constraint 4、pitfall 3、decision 2 |

**没被注入的探针对应的问题**（前 8 条）：

- HITL 选项不够用，能不能像 deepseek harness 那样让用户自己填，条目分页显示，别一次全堆出来？
- 为什么每次都要等流程走完才让我确认？能不能在对话中间就弹出来让我选，提交完再接着往下跑？
- 简历和面试场次在对话栏里怎么绑定选择？
- 用户想切换不同候选人的某轮面谈记录时，前端该怎样建立并呈现这两者的关联？
- 简历上的写法能优化吗？怎么写更好，要基于代码事实，别编造。
- 求职材料里那段描述是不是还能改得更到位？你建议怎么呈现才更靠谱，而且必须严格对照实际代码，不能虚构。
- git仓库链接要带上，简历里别写memory.json这种自定义文件名，也别用“写入钩子带硬deadline且全程fail-open”这种晦涩说法，讲技术亮点就行。
- 投递材料里请附上代码托管地址；描述项目时避免出现自造配置文件名，也不要用生僻拗口的表述，直接说明技术优势即可。

## 单相关假设有多错（人工判定子集）

还没有人工判定过"非目标"的行。这个子集用来回答一个问题：**单相关假设是不是把本来也该算对的记忆当成噪音罚了**。

标法：对每个探针，取两个检索器给出的、不是目标的那几条，判断"这条查询下这条记忆该不该被想起"。
写进 `recall1.csv` 的 `label` / `note` 列即可，不用改其它文件。
